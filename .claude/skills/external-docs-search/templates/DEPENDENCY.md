## 为什么用它
公历↔农历换算 + 时辰地支，避免手写农历换算表（CLAUDE.md §0-2 禁止写死未校验的表）。
**替代方案**：手写农历表 —— 被 §0-2 禁止；其他农历库 —— **未评估**（未解决问题 #2）。

## 安装 / 接入
`npm i lunar-javascript`（已在 `backend/package.json` dependencies；仅后端使用，前端经 `/api/compute`）。

## 鉴权与环境变量
无 —— 纯本地计算库，不需要密钥。

## 核心用法速查
- `Solar.fromYmdHms(y, m, d, h, mi, s).getLunar()` — 公历→农历　〔来源：`backend/src/lib/xiu.ts:23` + `backend/src/types/lunar-javascript.d.ts` · 本地类型声明〕
- `lunar.getMonth() / getDay()` — 农历月 / 日（本命宿只需这两个）　〔同上 · 本地类型声明〕
- `lunar.getTimeZhi()` — 时辰地支　〔来源：`backend/src/lib/xiu.ts:59` · 本地类型声明〕

```ts
import { Solar } from "lunar-javascript";
const lunar = Solar.fromYmdHms(1990, 6, 15, 10, 0, 0).getLunar();
lunar.getMonth(); // 农历月（闰月为负数）
```

## 常见坑与限制
- **农历闰月用负月份表示**（闰五月 = `-5`）　〔来源：`backend/src/lib/xiu.ts:25` · 官方仓库产物/本仓实测〕
- **`getXiu()` 返回「值日宿」，不是本命宿**；本项目本命宿走《宿曜经》算法，不用此方法　〔来源：`CLAUDE.md` §3 · 本项目结论〕
- 包**不自带 TypeScript 类型**，本仓自建 `backend/src/types/lunar-javascript.d.ts`（只声明实际用到的最小表面）。
