## 2. 目标 & 非目标

**目标**

1. 用户不需要懂塔罗，也能在 30 秒内完成一次完整体验：洗牌 → 报数 → 看三张牌（含正逆）+ 解读。
2. 抽牌过程**可解释、可复现**：用户清楚「我报的数字 = 从洗好的牌堆里翻第几张」；同一副牌序下，同样的数字必出同样的三张牌**且正逆一致**。
3. 解读内容**有出处、可核对**，措辞克制。**逆位不当成坏消息处理**（§10.2），读完是「有个视角可以想想」，不是「我完了」。

**非目标**（不是这一版要解决的）

- 不做「算得准不准」的竞争，不宣称任何预测能力。
- 不做内容深度的天花板（长篇个性化报告），MVP 求「完整、真实、不吓人」。
- 不做增长功能（分享 SDK / 裂变 / 付费）。

## 3. 核心 Flow

```
进入 /tarot
   ↓
系统自动洗牌：78 张随机排成一列（牌面朝下），并为每张独立掷定正位 / 逆位
   ↓  ——「牌已洗好」状态提示 + 本次牌序短码
用户在三个输入框里各填一个 1–78 的整数（三个数字不能重复）
   ↓
点击「抽牌」（或按 Enter）
   ↓
校验：不通过 → 就地报错，不抽牌；通过 → 按输入顺序翻开三张牌，各自带出洗牌时定好的正 / 逆位
   ↓
结果区：三张牌（位置 1/2/3 · 正 or 逆）+ 每张的位置化解读 + 综合解读 + 免责声明
   ↓
用户可「改数字重抽」（同一副牌序、正逆不变）或「重新洗牌」（牌序与正逆全部重排，结果清空）
```

> 用户**不选、也不能改**正逆位 —— 正逆是洗牌的一部分，跟牌序一起在用户报数之前就定死（理由见 §6.1）。

## 4. 页面结构

从上到下：

1. 页面标题「三张牌塔罗」+ 一句话说明（「先洗牌，再报三个数字」）。
2. **玩法说明**（常驻，3–4 行）：牌堆已经洗好、正面朝下排成 78 张的一列，每张牌的正逆也已经定好；你报的数字，就是从这一列里翻开第几张。**外加一句**：「逆位不是坏牌，只是换一个角度看同一张牌。」
3. **洗牌状态区**：显示「牌已洗好（本次牌序 #<短码>）」+「重新洗牌」按钮。
4. **输入区**：三个带标签的数字输入框 —— 「第一个数字（过去）」「第二个数字（现在）」「第三个数字（指引）」。
5. **主操作按钮**「抽牌」。
6. **错误提示区**：逐框错误 + 表单级错误（如重复）。
7. **结果区**（抽牌前隐藏或显示引导语「填入三个 1–78 的数字，点击抽牌」）：
   - 三张牌卡片（位置名 / 用户报的数字 / 牌名中英 / **正位 or 逆位标识** / 该朝向的关键词 / 位置化解读）；
   - 综合解读段落；
   - 「这不是预测」的收尾提示 + **免责声明**。
8. 页脚沿用全局 `Disclaimer`。

结果区布局需**适合整屏截图**（三张牌横向排列，窄屏纵向堆叠）。

## 5. 牌库定义

### 5.1 78 张构成（固定不变）

- **大阿卡纳 22 张**：0 愚者 The Fool … 21 世界 The World。
- **小阿卡纳 56 张**：四花色 × 14 张。
  - 花色：权杖 Wands · 圣杯 Cups · 宝剑 Swords · 星币 Pentacles。
  - 每花色：Ace、2–10、侍者 Page、骑士 Knight、王后 Queen、国王 King。
- 牌库**骨架**（id / 中英名 / arcana / suit / rank）以**固定顺序**定义在 `frontend/src/data/tarot-deck.ts`（大阿卡纳 0→21，然后 权杖→圣杯→宝剑→星币，每花色 A→King），`id` 为 1–78 的稳定编号。**释义文案分放** `frontend/src/data/tarot-readings.ts`（照搬主线 `xiu.ts` / `readings.ts` 的切法）。
  - ⚠️ 这个 `id` 是**牌库内部编号**，与用户输入的数字（洗牌后的位置序号）**不是一回事**，不得混用。

**中文译名 = 本项目内部标准（v0.3 定）**
取证确认**不存在任何权威中文标准**（无国标、无统一译法；中文维基自身用词都互相矛盾）。故以上表内译名**即为本项目定表**，全站统一，不再逐处商量：

| 需消歧处 | 本项目用 | 为什么 |
|---|---|---|
| III The Empress | **女皇** | 中文维基把 Empress 与宫廷牌 Queen **都写作「皇后」**，同屏必打架 |
| Queen（宫廷牌） | **王后** | 同上 |
| Pentacles | **星币** | 另见「钱币 / 五角星 / 金币 / 圆盘」等写法，本项目取星币 |
| Page | **侍者** | 另见「侍从 / 随从」 |

- About 页需加一句：**「塔罗牌的中文译名无权威标准，本项目采用此译法。」**
- 牌名以**今日通行 RWS 名**为准，不用韦特原书旧名（原书 VIII 作 *Fortitude*、XX 作 *The Last Judgment*、愚者编号作 *Zero* 且排在 20 与 21 之间）—— 这一差异只在把原文映射到牌时需要注意，不影响展示。

### 5.2 正位与逆位（v0.2 新增）

- **78 张牌全部支持逆位**，没有例外牌。一次抽牌的状态空间 = 78 × 2 = **156 种**。
- 正逆是**牌自身的朝向**，与它落在哪个位置无关：位置含义（§8）不因正逆改变，改变的是这张牌在该位置上说什么。
- 正逆由系统在**洗牌阶段**随机定下（§6.3），用户不可见、不可选、不可改，直到翻牌才揭晓。
- **逆位不是「反义词」，更不是「坏牌」** —— 内容纪律见 §10.2，这是本功能最大的红线风险点。
- **不使用任何牌面插图**：卡片用 `tokens.css` 变量绘制的统一样式（牌名 + 花色符号 + 朝向标识 + 关键词），不下载、不内嵌第三方牌面图（素材授权见 §17-d）。

## 6. 洗牌、定正逆与抽牌规则

### 6.1 洗牌（牌序）

- **时机**：进入页面时自动洗一次；此后只有点「重新洗牌」才重排。
  **必须在用户输入数字之前就把牌序和正逆全部定死** —— 不允许「拿到用户数字之后再决定发哪三张牌、或再决定这三张是正是逆」（那等于系统在挑牌，违背玩法承诺）。
- **算法**：Fisher–Yates 洗牌，随机源用 `crypto.getRandomValues`。
  - **禁止** `array.sort(() => Math.random() - 0.5)`（分布有偏，是经典 bug）。
  - **禁止**任何对结果的「兜底修正」（比如「避免连出三张宝剑」「保证至少一张大阿卡纳」「不要三张全逆」）—— 随机就是随机。

### 6.2 牌序标识

- 每次洗牌生成一个短码（如 6 位），**同时代表牌序与全部 78 张的正逆状态**：短码不变 ⇒ 这副牌一张都没动过。
- 短码仅用于 UI 展示与人工核对，不含任何用户信息，不上报。

### 6.3 定正逆（v0.2 新增）

- 洗好牌序后，**对 78 个位置逐一独立掷定朝向**：每张牌 **50% 正位 / 50% 逆位**，随机源同样用 `crypto.getRandomValues`。
- 朝向与牌序之间、三个位置彼此之间**相互独立**：不做任何配额（不保证「三张里至少一张正位」）、不做任何相关性设计。
- 因此三张全正、三张全逆都是合法结果，各自概率 1/8 —— **综合解读必须能优雅处理这两种极端**（§9.3 / §10.2）。
- 逆位概率固定 50%，**不做用户可调、不做「关闭逆位」开关**（见 §16 / §17-b）。

### 6.4 抽牌

- 用户输入的三个数字 = **洗好后牌堆的位置序号（1-indexed，第 1 张到第 78 张）**。
- 按**用户输入顺序**取牌：第一个数字 → 位置 1（过去），第二个 → 位置 2（现在），第三个 → 位置 3（指引）。不排序、不去重后重排。
- 每张翻出的牌**带出它在洗牌时被定下的朝向**，抽牌阶段**不二次掷骰**。
- **幂等**：同一副牌序 + 同样的三个数字 → 必然是同样的三张牌，**顺序一致、正逆也一致**。
- **改数字重抽**：允许，牌序与全部朝向不变。
- **重新洗牌**：牌序与全部 78 张的朝向一起重排，**必须清空已有结果**（不允许旧结果和新牌序同屏，会让人误以为结果被篡改）。

## 7. 输入校验

> 用户只输入三个数字，**不输入朝向**。本节不因 v0.2 改动。

### 7.1 规则

| # | 规则 |
|---|---|
| 1 | 三个输入均**必填** |
| 2 | 只接受**整数**（不接受小数、分数、表达式、字母、符号） |
| 3 | 范围 **1 ≤ n ≤ 78**（含两端） |
| 4 | 三个数字**互不重复**（同一张牌不能被翻两次） |
| 5 | 自动 `trim` 前后空格；**全角数字自动转半角**（中文输入法常见） |
| 6 | 允许前导零（`007` → 7） |
| 7 | 输入框 `inputmode="numeric"`、`maxlength=3`，移动端弹数字键盘 |

### 7.2 校验时机

- 点击「抽牌」或按 Enter 时**统一校验**；校验不通过则**不抽牌、不改动已有结果**。
- 已报错的输入框，用户一开始修改就立即清除该框的错误提示（不用等再次提交）。
- 每个输入框显示**自己的**错误；「数字重复」是表单级错误，同时把涉及的输入框标记为错误态。

### 7.3 错误文案

| 场景 | 页面反馈 |
|---|---|
| 某个输入为空 | 请填写第 N 个数字 |
| 输入小数（`1.5`） | 请输入整数，不支持小数 |
| 输入字母 / 符号 / 中文 | 请输入 1–78 之间的整数 |
| 输入 `0` 或负数 | 数字要在 1–78 之间 |
| 输入大于 78（`100`） | 数字要在 1–78 之间 |
| 三个数字有重复 | 三个数字不能重复，同一张牌不会被翻两次 |
| 前后有空格 / 全角数字 | 自动处理，不报错 |

- 错误提示**不能只靠颜色**表达，必须有文字，并与输入框以 `aria-describedby` 关联。

## 8. 三张牌的位置含义（牌阵定义）

固定三张牌阵，位置含义**写死、不让用户选**；**正逆位不改变位置含义**，只改变这张牌在该位置上说什么。

| 位置 | 名称 | 含义（给用户看的一句话） | 解读该写什么 |
|---|---|---|---|
| 1 | **过去 · 背景** | 是什么把你带到了现在这个位置 | 已经发生的经历、既有的习惯与条件、这件事的来路 |
| 2 | **现在 · 现状** | 你此刻正处在什么状态里 | 当下的处境、情绪、正在起作用的力量、你可能忽略的一面 |
| 3 | **指引 · 走向** | 如果顺着现在这样走下去，值得留意什么 | **可行动的提醒、可以问自己的问题、值得关注的倾向** |

**位置 3 的措辞纪律（重要）**：这一张叫「指引」不叫「结果」。文案一律写成**倾向 / 提醒 / 反问**，不得写成对未来的断言。
**逆位落在位置 3 时这条纪律照样成立，且要格外小心** —— 「逆位 + 未来位」是最容易被写成恐吓的组合。

- ✅ 「这张牌逆位时常被用来提醒：先把手上没收尾的事结掉，比急着开新局更省力。」
- ❌ 「逆位落在未来位，说明这件事最终会失败。」／「三个月内你会遇到贵人。」

三张牌之外还有一段**综合解读**（§9.3），负责把三个位置串成一条线。

## 9. 解读内容规格

### 9.1 每张牌的数据（78 张 × 正逆两套，全真、无占位）

**⚠️ v0.3 起正逆两侧不再对称**：正位有三段位置化解读，逆位只有一段「逆位视角」。理由见 §9.2 —— 原文逆位中位数只有 7 个词，硬撑成三段位置化等于纯编造。

```
TarotCardReadings {
  id, source,                       // source = 原文出处标注（全库统一，见 §9.2）
  upright: {
    sourceQuote,                    // 原文逐字（红线筛选后）—— 唯一「引用」的字段
    keywords[3], meaning,           // ↓ 以下全部为本项目编写
    byPosition { past, present, guidance }
  },
  reversed: {
    sourceQuote,                    // 原文逐字（红线筛选后）
    keywords[3], meaning,           // ↓ 以下全部为本项目编写
    reversedLens                    // 一段「逆位视角」，取代 byPosition
  }
}
```

| 字段 | 层 | 说明 |
|---|---|---|
| `sourceQuote` | **引用层** | 韦特原文**逐字**片段，经 §10 红线筛除后的保留子集。空串仅允许出现在圣杯二逆位（§9.2 特例） |
| `source` | 引用层 | 出处标注，全库统一 `A. E. Waite, The Pictorial Key to the Tarot, 1910` |
| `keywords` | **编写层** | 每套 **3 个**中文关键词（中性词，不用「凶」「劫」「破」这类**带凶义**的字，见下方判例） |
| `meaning` | 编写层 | 该朝向的通用释义，2–3 句 |
| `byPosition.*` | 编写层 | **仅正位**：三个位置上各 1–2 句 |
| `reversedLens` | 编写层 | **仅逆位**：一段「逆位视角」，2–3 句。与引擎提供的**位置框架句**拼接成文（§9.4） |

**引用层与编写层必须在页面上分区块显示**（§12），绝不混排 —— 这是 v0.3 口径的核心。

**关键词禁字的判例（v0.3 补 · 编排者 2026-08-09 裁定，可推翻）**

规则针对的是**凶义**，不是字形本身。验收扫描仍按字形拦截以保持可自动化，但下列中性用法**明确豁免**，加进扫描白名单：

| 豁免词 | 出现处 | 理由 |
|---|---|---|
| **说破** / **说破了** | 宝剑一、宝剑三的关键词 | 义为「挑明、讲清楚」，与「破财 / 破败」的凶义无关 |

- 新增豁免必须走同样流程：**逐条列进这张表**，不许在扫描器里加通配、也不许直接放宽字形规则。
- 判定标准：该词在现代汉语常用义里**是否带负面预示**。带 → 换词；不带 → 进白名单。

**内容量（v0.3 重算）**
| 项 | 数量 |
|---|---|
| `sourceQuote`（原文摘录 + 红线筛选） | 78 × 2 = **156 条** |
| 关键词 | 78 × 2 × 3 = **468 个** |
| `meaning` | 78 × 2 = **156 段** |
| 正位 `byPosition` | 78 × 3 = **234 段** |
| 逆位 `reversedLens` | 78 × **1** = **78 段** |
| **位置化/视角段落合计** | **312 段**（v0.2 原为 468 段） |

### 9.2 内容来源纪律（对齐 CLAUDE.md §0-2「不臆造」）

> **v0.3 重写。** 取证结论（`docs/external/tarot-rws-meanings.md`，已由编排者独立抽验复核）推翻了 v0.2 的假设：
> - 逆位释义**中位数 7 词、83% 是纯词表**（如愚者逆位全文即「Negligence, absence, distribution, carelessness, apathy, nullity, vanity.」），仅 1 张成段；
> - 多张逆位是**回指**（太阳「The same in a lesser sense.」、宝剑五「The same; burial and obsequies.」），脱离正位读不通；
> - 原文**大面积违反本项目 §10 红线**：`calamity` `mortality` `imprisonment` 等恐吓词密集，且**按性别/发色/肤色断言人物**（"A dark woman, countrywoman…"）直撞 §10.1-9；
> - **无第二个可用公版源**：Papus 1896 全书 `Reversed` 出现 0 次；Mathers 1888 全文遍寻未获；Golden Dawn *Book T* 在 archive.org 为个人上传、无 license/rights 字段，版权不可核实。
>
> 结论：「从 7 个词整理出 3 段位置化解读」是创作不是整理。继续声称「整理自公版」就是**冒充**，正是 CLAUDE.md §0-2 要禁的事。故改为下述双层口径。

**核心口径：引用层与编写层分离，各自诚实标注**

| 层 | 内容 | 纪律 |
|---|---|---|
| **引用层**（`sourceQuote` + `source`） | 韦特原文**逐字**片段 | 一字不改，只做**红线筛除**（见下）。标 `A. E. Waite, The Pictorial Key to the Tarot, 1910` |
| **编写层**（`keywords` / `meaning` / `byPosition` / `reversedLens`） | 中文关键词与阐释 | **本项目编写**，页面上明确如此标注。**不得**声称出自韦特、不得冒充传统定论 |

1. **取源范围**：只用 PKT **§2 `THE LESSER ARCANA`（56 小牌主条目）+ §3 `GREATER ARCANA`（22 大牌）**。
   **弃用 §4 `SOME ADDITIONAL MEANINGS`** —— Waite 自述该节由他人供稿、「与图像设计几乎无关」，且与主条目互相矛盾（宝剑四逆位：主条目 "Wise administration" vs §4 "A certain success following wise administration"）。口径单一才可核对。
2. **红线筛除是强制的，不是可选的**。`sourceQuote` 只保留经 §10.1 / §10.2 筛查后的词，**必须剔除**：
   - 按性别 / 发色 / 肤色 / 族裔断言人物的表述（§10.1-9）；
   - `calamity` `disaster` `mortality` `imprisonment` `ruin` `evil fatality` 等灾难与恐吓词（§10.1-5、§10.1-8）；
   - 疾病、诉讼、破财类断言（§10.1-2、§10.1-3、§10.1-4）。
   筛除后若该牌 `sourceQuote` 所剩不足 2 词，允许留空并在核对清单标注「原文全数触线，已略」。
3. **回指型逆位**（"The same in a lesser sense." 类）**不得单独作为 `sourceQuote` 呈现** —— 它脱离正位无意义。此类牌的 `sourceQuote` 取其**实义部分**（如塔逆位取 "oppression, tyranny"），无实义部分则留空并标注。
4. **编写层不得由正位机械取反生成**（「勇气 → 没有勇气」这种）。逆位阐释走 §10.2 规定的五种中性框架。
5. **特例 —— 圣杯二**：78 张里**唯一**主条目无 `Reversed` 的牌。其逆位 `sourceQuote` **留空**并标注「原文缺逆位依据」；**不去 §4 取那个孤零零的 "Passion."**（口径已定为只用主条目，且单词无信息量）。
6. **不得宣称韦特权威**。原书 §3 末尾 Waite 本人写道：*"The allocation of a fortune-telling aspect to these cards is the story of a prolonged impertinence."*（把算命属性安到这些牌上，是一场旷日持久的僭妄。）故 `source` 只作**出处标注**，页面措辞不得出现「韦特权威解读」「正统释义」类表述（并见 §10.1-10）。
7. **逆位 50% 与原书无关**：全书唯一的逆位指令是 §8「Shuffle the entire pack and **turn some of the cards round**」——「some」，未给比例。§6.3 的 50/50 是**产品决定**，任何文案都不得标称「依韦特」。
8. 允许 AI 起草编写层，但**必须人工定稿**；引用层必须逐条对回 `docs/external/tarot-rws-meanings.md` 的原文。
9. 未定稿条目页面上必须显式标「示例（占位）」—— 但**验收要求零占位**（§15）。

### 9.3 综合解读（三张牌串起来）

- **不接 LLM、不在运行时生成文案**。综合段落由**规则模板 + 人工定稿的文案库**拼装：
  - 规则维度：大阿卡纳数量（0/1/2/3）、花色分布（是否集中在某一花色）、宫廷牌数量、**逆位数量（0/1/2/3）**。
  - 每种情形对应一段预先写好、人工审过的文字，模板里只插入牌名。
- **逆位数量这一维必须写成中性描述，禁止吉凶定性**：
  - ✅ 三张全逆 → 「这次三张都是逆位，整体偏『向内看』—— 比起对外推进，牌面更多在说慢下来、回头看看。」
  - ❌ 三张全逆 → 「运势低迷 / 阻碍重重 / 诸事不宜」。
  - ✅ 三张全正 → 「这次三张都是正位，能量比较外放。」　❌ 「大吉 / 一切顺利 / 好运连连」。
  - **正位多不等于结论更好，逆位多不等于结论更差** —— 两侧文案的情绪基调必须对称。
- 综合段落长度 3–5 句，收尾固定是一句**把主动权交回用户**的话（如「牌只提供一个视角，怎么选还是你说了算」）。
- 规则组合必须**穷尽覆盖**：任何一种抽牌结果（含三张全正、三张全逆）都能拼出一段合法文案，不允许出现空白或兜底占位符。

### 9.4 位置框架句（引擎层 · v0.3 新增）

因为逆位不再有逐位置文案（§9.1），逆位牌在三个位置上的呈现由**引擎的位置框架句** + **内容层的 `reversedLens`** 拼接成文。

| 位置 | 框架句（引擎提供，示意） |
|---|---|
| 1 过去 · 背景 | 「回头看这一段——」 |
| 2 现在 · 现状 | 「就眼下的状态——」 |
| 3 指引 · 走向 | 「就这件事往下走，值得留意的是——」 |

- 框架句归 **引擎（`lib/tarot.ts`）**，属规则层；`reversedLens` 归 **内容（`tarot-readings.ts`）**。归属不得混淆。
- 正位不走框架句，直接用 `byPosition` 的对应段落。
- 框架句本身也要过 §10 红线（位置 3 的框架句尤其不得写成未来断言）。
- 拼接后的成文必须读得通顺，不能出现「框架句 + 逆位视角」语气打架。

**`reversedLens` 的写法约束（v0.3 实测后补，血泪教训）**

首批 22 张交付时 **22/22 条**都以「这张牌逆位时，……」开头，拼出来是「回头看这一段——这张牌逆位时，重点常在……」。三个问题：语气从第二人称情境猛切到第三人称评牌；**框架句被这个开头吞掉**，导致三个位置读起来几乎没差别（位置感白做）；用户抽到三张逆位会连看三遍同一句式。故补以下硬规则：

1. **必须能直接接在框架句后面成句** —— 写的时候就按「接在破折号后面」来写，不要当成独立段落起头。
2. **禁止以复述朝向的话开头**：「这张牌逆位时」「逆位时」「逆位常被读成」等一律不许做开头。卡片上已有「逆位」文字标识、引擎已给框架句，再说一遍是三重冗余。
3. **不得带位置指向**：不能出现「未来」「接下来会」「过去曾经」这类词 —— 同一段要能同时接在三个位置的框架句后面。
4. **开头句式要有变化**：78 条不许挤在两三个模子里（首批 19/22 撞在「重点常在 / 可…… / 值……」三种开头上）。
5. 自查方法：把这段文字**逐一接在三条框架句后面各读一遍**，三次都通顺才算过。

## 10. 解读里「不给什么」（红线）

> 对齐 `CLAUDE.md` §0-1 / §0-4 与主线 PRD §12。**以下任一条被违反，视为验收不通过。**

### 10.1 内容黑名单 —— 一律不写

1. **不预测确定性事件**：不给「会 / 一定 / 必然 / 注定」式断言，不给具体时间点预测（「三个月内」「明年」）。
2. **不做医疗判断**：不涉及疾病、诊断、用药、心理健康诊断、怀孕与生育结果。
3. **不给投资 / 财务建议**：不出现买入卖出、行情、盈亏、「破财」「漏财」等表述。
4. **不给法律 / 重大人生决策指令**：不写「你该分手 / 该结婚 / 该辞职 / 该打官司」。
5. **不制造焦虑与恐吓**：禁止「大凶」「血光」「劫难」「必须化解 / 转运」这类句式，也不得暗示「不处理会出事」。
6. **不诱导付费迷信**：不出现任何付费解灾、开运物、进阶付费解读的引导（本版本整体不含付费）。
7. **不涉及第三方**：不对用户之外的具体人做判断（「你伴侣正在……」「你老板对你……」）。
8. **不涉及生死与自我伤害**：不出现死亡预言、寿命判断，或任何可能被读成鼓励自伤 / 绝望的表述（「死神」牌按传统释义写「结束与转变」，不写字面死亡）。
9. **不做身份判断**：不涉及性取向、宗教、族裔、精神状态等敏感身份的推断。
10. **不宣称权威 / 准确性**：不写「塔罗显示」「命运告诉你」式口吻，也不写「准确率」。

### 10.2 逆位专项纪律（v0.2 新增 —— 本功能最大的红线风险点）

逆位在坊间常被简化成「坏 / 凶 / 警告」，这与本项目「不制造焦虑」的定位直接冲突。硬性要求：

1. **逆位 ≠ 坏牌**。全站不得把正逆写成吉凶二元、好坏对立、加分减分。
2. **逆位释义只走中性框架**，从下列角度切入：
   - 能量**向内**（对外表达变成自我消化）；
   - **尚未展开 / 时机未到**；
   - **过度或不足**（同一特质用力过猛或用得不够）；
   - **卡住待疏通**；
   - **提醒回看**（先处理旧的，再开新的）。
   不得用「反面 = 灾祸 / 失败 / 惩罚」的框架。
3. **禁止「逆位警告」句式**：不写「这是一个警告」「牌在提醒你危险」「逆位说明有阻碍在等着你」。
4. **敏感牌逆位必须人工逐条过**：死神、塔、恶魔、宝剑三 / 九 / 十、月亮，以及所有含冲突意象的牌，逆位文案单独审一遍，禁止字面灾难化。
5. **逆位数量不做吉凶定性**（§9.3）；三张全逆的综合文案必须与三张全正情绪基调对称。
6. **UI 不得把逆位表达成危险**：不用红色 / 警告色 / 感叹号 / 警示图标标记逆位（§12）。
7. **玩法说明里必须明说**：「逆位不是坏牌，只是换一个角度看同一张牌。」

### 10.3 措辞规范 —— 该怎么写

| 不要这样 | 改成这样 |
|---|---|
| 「你注定会失败」 | 「这张牌常被解读为『暂时停一停』——现在急着推进，代价可能更高」 |
| 「你会破财」 | 「这张牌提醒的是对资源的珍惜，可以问问自己：最近有没有在硬撑什么」 |
| 「必须化解」 | 「如果你也有同感，或许值得先跟当事人聊一次」 |
| 「三个月内有贵人」 | 「这张牌指向『借力』——你身边有没有本来就可以问的人？」 |
| 「逆位，说明这事要黄」 | 「逆位时这张牌常被读成『力气用在了里面』——推进看着慢，未必是停住了」 |
| 「三张全逆，运势很差」 | 「三张都是逆位，整体偏向内省——这次的牌更想让你往回看，而不是往前冲」 |

统一句式工具箱：「常被解读为……」「一种可能的视角是……」「你可以问问自己……」「如果这说中了什么，那就……」。

### 10.4 免责声明

- 结果区**底部固定显示**完整免责声明（复用 `components/Disclaimer.tsx`），不折叠、不需要点开：
  > 内容为传统文化 / 娱乐参考，不构成任何人生、医疗、投资、婚姻等决策建议。
- 页面顶部玩法说明里另有两句轻量提示：「这是一个娱乐向的自我反思小工具，不预测未来。」+「逆位不是坏牌。」
- 全局页脚的 compact 免责声明照常保留。

## 11. 数据模型（前端内存态，不落库）

```
Orientation = 'upright' | 'reversed'

// 骨架（data/tarot-deck.ts）—— 结构，无文案
TarotCard   { id, nameZh, nameEn, arcana, suit?, rank? }

// 释义（data/tarot-readings.ts）—— 引用层 + 编写层，正逆不对称
TarotCardReadings {
  id, source,                                   // 引用层：全库统一出处标注
  upright:  { sourceQuote,                      // 引用层：原文逐字（红线筛选后）
              keywords[3], meaning,             // 编写层
              byPosition{past,present,guidance} },
  reversed: { sourceQuote,                      // 引用层：原文逐字（红线筛选后）
              keywords[3], meaning,             // 编写层
              reversedLens }                    // 编写层：一段逆位视角（无 byPosition）
}

DeckOrder   { shuffleCode: string,
              order: number[],              // order[i] = 第 i+1 个位置上的牌 id
              orientations: Orientation[] }  // orientations[i] = 第 i+1 个位置上那张牌的朝向

DrawInput   { n1: number, n2: number, n3: number }   // 1–78，互不相同

DrawResult  { shuffleCode,
              picks: [{ position, inputNumber, card, orientation }] × 3,
              summary: string }
```

- `order` 与 `orientations` **等长（78）且一一对应**，都在洗牌时生成、之后只读。
- 全部存于组件状态；**不写 localStorage、不发请求、不进 Supabase**。
- 刷新页面 = 重新洗牌（牌序与朝向都重排）、结果清空 —— 这是预期行为，需在 UI 上说明。

## 12. 视觉 / 交互 / 无障碍

**通用**

- **一切颜色 / 字体 / 间距 / 圆角 / 阴影只走 `var(--...)`**，禁止手写 hex / px 魔法值（CLAUDE.md §4-1）。
- 沿用东方夜空单主题（墨蓝底 + 鎏金强调），不做浅色版。牌卡沿用现有卡片样式语言，不引入新的设计语言、不加 UI 组件库。
- 四象色（`--xiang`）是二十八宿主线的分类语义色，**塔罗页不得挪用**。四个花色如需区分，用中性层级（描边 / 透明度 / 花色符号）表达，或另行申请 token（改 token 走 `tokens.css`，不在页面里私自定义）。

**引用层与编写层的分区块呈现（v0.3 新增 · 本版口径的核心）**

- 每张牌卡上，**原文依据**与**本项目编写的阐释**必须是**视觉上可区分的两个区块**，不得混排成一段。
- 引用区块要素：`sourceQuote` 原文（英文原样）+ 出处署名 `—— A. E. Waite《The Pictorial Key to the Tarot》1910`。样式上取「引文」质感（如左侧竖线 + 降一档字号），走 `var(--...)`。
- 编写区块要素：中文关键词、释义、位置化解读 / 逆位视角，**区块起始处需有明确标识**（如「以下为本项目编写的现代阐释」）。
- `sourceQuote` 为空的两类情形（圣杯二逆位「原文缺逆位依据」、原文全数触线「已略」）必须**显示该说明文字**，不能静默留白 —— 静默留白会让人以为原文就是那样。
- 页面任何位置**不得**出现「韦特权威解读」「正统释义」「原著认为你……」这类把编写层挂到韦特名下的表述（§9.2-6）。

**逆位的视觉表达（v0.2 新增）**

- 卡片上用**文字标识**「正位」/「逆位」，紧跟牌名（如「宝剑三 · 逆位」）；可另配一个中性的方向符号（如 ↑ / ↓ 或倒置的花色符号）。
- **正文不得整体旋转 180°**（不可读，且屏幕阅读器与选中复制都会坏）。若要做「翻转感」，只允许旋转卡面的装饰性图形层，文字保持正向。
- **不得用红色 / 警告色 / 感叹号 / 警示图标**表达逆位（红线 §10.2-6）。正逆两种状态的视觉权重应当相当 —— 不能让逆位看起来「更严重」。
- 正逆**不能只靠图形或旋转表达**，必须有文字标识（无障碍 + 色觉友好双重要求）。
- 屏幕阅读器读到的卡片名必须含朝向（「宝剑三，逆位」），用 `aria-label` 或可见文本实现。

**其他交互 / 无障碍**

- 翻牌动画可有，但必须尊重 `prefers-reduced-motion`；动画不得延迟内容可读（reduced-motion 下直接出结果，朝向标识直接可见）。
- 响应式：手机竖屏三张牌纵向堆叠，桌面横向并排。
- 输入框有可见 `<label>`（不能只靠 placeholder）；错误用 `aria-describedby` 关联且不只靠颜色；「抽牌」按钮键盘可达；Enter 触发抽牌；结果区更新时用 `aria-live="polite"` 播报。

## 15. 验收标准（人工可判断，做完对照这个）

**抽牌逻辑**

- [ ] 进入 `/tarot` 自动完成洗牌与定正逆，页面显示牌序短码；不点「重新洗牌」时短码不变。
- [ ] 输入 `1 / 2 / 3` 抽牌，翻出三张牌且各自带朝向；不重新洗牌、重复点击「抽牌」，**三张牌与三个朝向完全一致**（幂等）。
- [ ] 同一副牌序下改数字再改回来，得到的牌与朝向不变。
- [ ] 点「重新洗牌」后，旧结果被清空，短码变化；再输同样三个数字，牌与朝向**通常不同**。
- [ ] 输入顺序决定位置：`5 / 60 / 12` 与 `12 / 60 / 5` 得到的三张牌（含朝向）集合相同，但位置分配不同。

## 16. Out of Scope（本版本明确不做）

**玩法**

- 三张牌以外的牌阵（凯尔特十字、关系牌阵、单张日签等）。
- 用户自选牌阵或自定义位置含义。
- **用户手动切换某张牌的正逆** —— 朝向由洗牌决定，不可改。
- **「关闭逆位」开关 / 用户可调逆位概率**（固定 50%，见 §17-b）。
- 用户自由文本提问 / 选主题（事业·感情·财运）后的定向解读。
- 每日一牌、连续签到、抽牌次数限制或冷却。
- 真人手动洗牌 / 切牌 / 拖拽选牌等拟真交互。

**内容**

- 真实牌面插图（RWS 或任何第三方牌面素材）—— 授权未取证前不引入，见 §17-d。
- AI 对话式解读、运行时 LLM 生成文案。
- 牌与牌之间的组合专属解读（156×156 组合库）。
- 逆位的流派差异并列呈现（「元素失衡说」「阻滞说」「时机未到说」等）—— 只用一套统一口径。
- 元素 / 数字学 / 占星对应等进阶体系。
- 多语言（英文版）。

**工程 / 产品**

- 后端接口、数据库落库、抽牌记录持久化。
- 登录、History 页面里回看塔罗记录。
- 分享卡片生成 / 分享 SDK / 社交传播功能。
- 付费、会员、任何形式的变现。
- 与二十八宿本命宿的联动解读（塔罗 × 星宿合盘）。
- 埋点 / 用户行为分析。
