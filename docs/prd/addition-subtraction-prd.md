# 加减法计算页面 PRD

## 1. 产品概述

开发一个简单的整数加减法计算页面。用户输入整数 A、整数 B，选择加法或减法，点击“显示答案”后查看计算结果。

- 产品名称：整数加减法计算器
- 产品形态：单页面 Web 应用
- 版本：MVP 1.0
- 目标用户：需要快速进行基础整数运算的用户

## 2. 产品目标

- 支持两个整数的加法和减法运算。
- 操作简单，用户无需学习即可使用。
- 对空值和非法输入提供明确提示。
- 计算结果准确、清晰。

## 3. 页面结构

页面从上到下包括：

1. 页面标题：“整数加减法计算器”
2. 整数 A 输入框
3. 运算类型选择：
   - 加法（+）
   - 减法（−）
4. 整数 B 输入框
5. “显示答案”按钮
6. 结果展示区域
7. 输入错误提示区域

## 4. 功能需求

### 4.1 输入整数 A

- 必填。
- 仅允许输入整数。
- 支持正整数、负整数和 0。
- 不接受小数、字母或其他非数字字符。

### 4.2 输入整数 B

- 必填。
- 校验规则与整数 A 相同。

### 4.3 选择运算类型

用户可以选择：

- 加法：结果为 `A + B`
- 减法：结果为 `A − B`

默认选择“加法”。

### 4.4 显示答案

用户点击“显示答案”按钮后：

- 如果两个输入均合法，立即显示计算结果。
- 如果存在非法输入，不进行计算，并显示对应的错误提示。
- 用户修改输入后再次点击按钮，应使用最新输入重新计算。

### 4.5 结果展示

结果区域建议显示完整算式，例如：

- `5 + 3 = 8`
- `5 − 8 = -3`

用户尚未完成计算时，结果区域可以隐藏或显示提示：“请输入两个整数并点击显示答案”。

## 5. 输入校验与异常处理

| 场景 | 页面反馈 |
|---|---|
| 整数 A 为空 | 请输入整数 A |
| 整数 B 为空 | 请输入整数 B |
| 输入小数 | 请输入整数，不支持小数 |
| 输入字母或特殊字符 | 请输入有效的整数 |
| 输入前后有空格 | 自动忽略前后空格 |
| 计算结果为负数 | 正常显示负数结果 |
| 计算结果为 0 | 正常显示 0 |

当输入错误时，应在对应输入框附近显示提示，并通过明显的视觉状态标记错误输入框。

## 6. 交互流程

1. 用户进入页面。
2. 输入整数 A。
3. 选择加法或减法。
4. 输入整数 B。
5. 点击“显示答案”。
6. 系统校验输入：
   - 校验通过：显示完整算式和结果。
   - 校验失败：显示错误提示，等待用户修改。
7. 用户可以修改输入并重新计算。

## 7. 界面要求

- 页面布局简洁，核心计算区域居中显示。
- 输入框应具有清晰标签，不能只依赖占位文字。
- “显示答案”按钮应具有明显的主操作样式。
- 计算结果字体应比普通文字更醒目。
- 页面需要适配手机和桌面端。
- 用户按下 Enter 键时，可以触发计算。
- 错误信息应清晰易懂，不能只通过颜色表达。

## 8. 验收标准

- 输入 `2`、选择加法、输入 `3`，结果显示 `2 + 3 = 5`。
- 输入 `2`、选择减法、输入 `3`，结果显示 `2 − 3 = -1`。
- 输入 `-5` 和 `3`，可以正确完成加减法。
- 输入 `0` 时可以正常计算。
- 任一输入为空时，不显示计算结果并提示必填。
- 输入 `1.5`、字母或特殊字符时，不执行计算并提示输入整数。
- 修改输入后重新点击按钮，结果同步更新。
- 手机和桌面浏览器中页面均可正常使用。

## 9. 非功能需求

- 点击按钮后应即时显示结果，无明显等待。
- 页面不需要登录。
- 用户输入和计算结果不需要保存。
- MVP 阶段不需要后端服务。
- 界面应符合基本无障碍要求，包括键盘操作和明确的表单标签。

## 10. MVP 不包含

- 乘法和除法。
- 小数、分数或复杂表达式。
- 历史计算记录。
- 用户账户和云端同步。
- 科学计算功能。
- 多步骤连续运算。
